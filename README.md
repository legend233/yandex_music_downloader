# Yandex music downloader
### Основано на:
#### * [MarshalX/yandex-music-api](https://github.com/MarshalX/yandex-music-api)
#### * [Telegram Bot API](https://github.com/eternnoir/pyTelegramBotAPI)
#### * [music-tag](https://github.com/KristoforMaynard/music-tag)

Telegram-бот для скачивания прямых альбомов артиста, отдельных альбомов/сборников, аудиокниг и подкастов по ссылкам Яндекс Музыки. Поиск артиста по имени доступен отдельно, с выбором результата и подтверждением загрузки по ID. Плейлисты и отдельные треки пока не поддерживаются.

Для работы необходимо:
1. [Токен вашего яндекс аккаунта](https://github.com/MarshalX/yandex-music-api/discussions/513#discussioncomment-2729781)
2. [Токен телеграмм вашего бота](https://lifehacker.ru/kak-sozdat-bota-v-telegram/)
3. Числовой ID разрешённого пользователя Telegram (не ID чата и не @username).

# Установка
## Linux (Python 3.10+)
Файловый менеджер использует Linux/POSIX `dir_fd` и `O_NOFOLLOW`. Для других систем используйте Linux-контейнер.
    1. открыть терминал
    2. выбрать каталог установки
    3. git clone 'THIS_PROJECT'
    4. cd yandex_music_downloader
    5. pip install -r requirements.txt
    6. nano .env
______________ 
#### .env

    TELEGRAMM_TOKEN=YOUR_TOKEN
    TELEGRAM_ALLOWED_USER_ID=123456789
    YA_TOKEN=YOUR_TOKEN
    DOWNLOAD_PATH_MUSIC=YOUR_DOWNLOAD_PATH
    DOWNLOAD_PATH_BOOKS=YOUR_DOWNLOAD_PATH
    DOWNLOAD_PATH_PODCASTS=YOUR_DOWNLOAD_PATH

Образец всех настроек — `.env.example`. `TELEGRAM_ALLOWED_USER_ID` обязателен: при отсутствии или неверном значении бот не запускается. Сообщения и нажатия кнопок от других пользователей молча игнорируются до обработки диалога. Проверяется именно `from_user.id`. В общих чатах ответы разрешённому пользователю видны участникам — для приватных файлов используйте личный чат с ботом.

Необязательные `TELEGRAM_PROXY_URL` и `YA_PROXY_URL` задают независимые прокси, например `socks5://user:pass@host:port`. Пустое значение означает прямое подключение.

# Использование
1. Отправьте команду вашему телеграм боту:

    /start - открыть меню и постоянную клавиатуру
    /download - скачать музыку, книгу, подкаст с яндекс музыки
    /files - просмотреть скаченное и получить в сообщении через телеграм
    /search - найти артиста по имени и выбрать его дискографию для загрузки
    /cancel - отменить текущий диалог, но не уже поставленные загрузки


2. Под полем ввода постоянно доступны **📥 Скачать** и **📂 Файлы** — эквиваленты `/download` и `/files`. Остальные кнопки находятся под сообщениями.
3. В меню скачивания выберите тип и отправьте ссылку: `https://music.yandex.ru/artist/123` для артиста или `https://music.yandex.ru/album/123` для альбома, книги и подкаста. Поддерживаются также домены `music.yandex.com`, `.by`, `.kz`, `.uz`, `.com.tr`; параметры ссылки не влияют на ID. Короткие ссылки и ссылки на отдельные треки не поддерживаются.
4. Для поиска по имени выберите **🔎 Поиск артиста по имени** или `/search`. Выберите артиста из результатов (есть страницы) и подтвердите скачивание. Скачиваются все страницы его прямых альбомов; гостевые участия вне этой дискографии не гарантируются.
5. Подтверждение добавляет задачу один раз. Переход в другое меню делает старые кнопки неактивными. Очередь и диалоги хранятся в памяти и не переживают перезапуск.
6. Файлы отображаются страницами по 15, с переходом по каталогам и ZIP-архивом выбранного подкаталога. Архивирование корня, символические ссылки, скрытые и служебные файлы запрещены. Показываются поддерживаемые аудиоформаты, обложки, тексты, PDF и EPUB. Размер отправляемого файла ограничен Telegram; архивирование и отправка могут задерживать обработку команд.
Файлы скачиваются в каталоги, заданные переменными `DOWNLOAD_PATH_MUSIC`, `DOWNLOAD_PATH_BOOKS` и `DOWNLOAD_PATH_PODCASTS`.

Музыка, аудиокнига, подкасты скачиваются в максимальном доступном качестве до 320 kbps с записанными тегами, обложкой, текстом песни (в тег и в одноименный файла.txt), описанием книги, выпуска, если есть на яндексе.

Логика тегов в этом обновлении не менялась. Существующие аудиофайлы не ретегируются.

## Проверки
`python -m unittest discover -s tests -v` — автономные тесты с подменой Telegram и Yandex API, без токенов и сетевых запросов. Зависимости устанавливаются из `requirements.txt`.

В CI тесты запускаются через pytest (он также поддерживает unittest). Отчёт `test-results/junit.xml` публикуется как JUnit artifact даже при падении тестов и хранится 2 недели. GitLab показывает результаты в pipeline и виджете тестов на странице MR. Тесты выполняются и в `main`, чтобы у сравнения была базовая версия. Как в shieldsurf-backend, используется pipeline ветки; отдельный дублирующий MR pipeline отключён.

Локальная проверка отчёта: `pip install pytest`, затем `python -m pytest tests/ --junitxml=test-results/junit.xml`.

## Автодеплой через Portainer
После успешных тестов и публикации образа `$CI_REGISTRY_IMAGE:latest` из `main` job `deploy-main` обновляет существующий стек **yandexdownloader** на окружении **pve-2-docker**. Деплои сериализованы через `resource_group`. Из feature-веток и тегов автоматического деплоя нет.

В GitLab → Settings → CI/CD → Variables настройте (или наследуйте из группы):
- `PORTAINER_URL` — адрес того же Portainer, что используется shieldsurf-backend;
- `PORTAINER_API_TOKEN` — токен с доступом к нужному окружению и стеку; хранить как masked/protected variable, не в репозитории;
- при необходимости `PORTAINER_INSECURE=true` — отключение проверки TLS, по умолчанию проверка включена.

Если секреты protected, ветка `main` должна быть protected. Переменные соседнего проекта автоматически не наследуются.

Перед первым деплоем проверьте в Portainer:
- стек ссылается на `registry.gitlab.com/vtechnology-ru/yandex_music_downloader:latest`, а не на старый образ Docker Hub; доступ к приватному registry настроен;
- в окружении контейнера задан корректный `TELEGRAM_ALLOWED_USER_ID`, а также токены и каталоги бота.

Скрипт `scripts/deploy.py` не заменяет compose из репозитория: он получает определение стека и его переменные из Portainer и возвращает их без изменений с принудительным скачиванием образа. Стек не создаётся автоматически. Скрипт ожидает активного статуса Portainer; это не проверка работоспособности Telegram-бота. При ошибке или таймауте job завершается неуспешно.

`python scripts/deploy.py --dry-run` проверяет поиск окружения и стека, не обновляя их (нужны переменные доступа). Обычный запуск без `--dry-run` выполняет реальный деплой.
